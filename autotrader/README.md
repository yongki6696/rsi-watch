# BTC 자동매매 봇 (차슐랭 스타일: 지지·저항 / 매물대 / 유동성 함정)

비트코인 차트 분석 채널 **「차슐랭ㅣ비트코인 분석」**의 분석 방식(핵심 가격대, 매물대, 유동성 스윕, 중기 방향)을 규칙으로 옮겨 다음 기능을 하나의 코드로 제공합니다.

- **백테스트**: 과거 데이터로 규칙 검증
- **모의매매**: 실시간 시세에 가상 주문
- **실거래**: ccxt를 통해 거래소에 실제 주문

> ⚠️ **먼저 읽어 주세요**
> - 이 규칙은 영상 자막을 직접 보지 못한 상태에서 영상 제목과 설명을 바탕으로 **추정**한 것입니다. 자세한 내용은 [RULES.md](RULES.md)에 있습니다.
> - 실제 시세(2019~2026) 백테스트에서 **수익 우위가 확인되지 않았습니다.** [결과](#실데이터-백테스트-결과)를 확인하세요.
> - 기본 설정은 **모의매매**입니다. 실거래는 테스트넷에서 충분히 검증한 뒤 본인 책임으로만 하세요.
> - 이 프로그램은 투자 권유가 아닙니다.

## 동작 방식

```
매 4시간봉 마감마다
 ├─ 중기 방향: 일봉 EMA50/200 → 상승이면 롱만, 하락이면 숏만
 ├─ 핵심 가격대: 스윙 고점·저점(2회 이상 반응) + 매물대(볼륨 프로파일) → 지지·저항 구간
 ├─ 셋업 A 함정(스윕): 지지 아래를 꼬리로 찌르고 거래량 동반 회복 마감 → 롱 (저항 위는 숏)
 ├─ 셋업 B 리테스트: 저항 돌파 후 첫 되돌림에서 지지 확인 → 롱 (반대는 숏)
 ├─ 손절: 꼬리/구간 바깥 + 0.2ATR  │  목표: 다음 핵심 가격대 (없으면 2R)
 ├─ 손익비 1.5 미만이면 패스, +1R 도달 시 본절 이동
 └─ 자금관리: 1회 손실 1%, 하루 -3% 또는 3연패 시 그날 중지, 최대 3배
```

백테스트와 실시간 매매는 같은 `strategy.py`, `trade.py`, `risk.py`를 씁니다. 그래서 백테스트에서 본 규칙이 실거래에서도 그대로 동작합니다. 신호는 봉이 마감된 뒤 과거 데이터만으로 계산하고(미래 참조 없음, 테스트로 검증), 진입은 다음 봉에서 합니다.

## 설치

```bash
cd autotrader
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q          # 40개 테스트
python -m bot demo           # 합성 데이터로 설치 확인 (수익률은 의미 없음)
```

## 사용법

```bash
cp config.example.yaml config.yaml          # 설정 복사 후 수정

# 1) 과거 데이터 받기 (공개 API, 키 불필요)
python -m bot fetch -c config.yaml --since 2019-01-01

# 2) 백테스트 → results/trades.csv, results/equity.csv
python -m bot backtest -c config.yaml
python -m bot backtest -c config.yaml --start 2019-01-01 --end 2024-01-01   # 기간 나눠 검증

# 3) 모의매매 (실시간 시세 + 가상 주문, 상태는 paper-state.json)
python -m bot run -c config.yaml

# 4) 실거래 (테스트넷부터!)
export EXCHANGE_API_KEY=...  EXCHANGE_API_SECRET=...
#   config.yaml 에서 live.enabled: true, exchange.sandbox: true 로 먼저 테스트넷 검증
python -m bot run -c config.yaml --live
```

- `--once`: 한 번만 판단하고 종료합니다. cron으로 돌릴 때 씁니다.
- 텔레그램 알림: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 환경변수를 설정하면 진입·청산·오류를 알려 줍니다.
- 다른 CSV 사용: `--csv 경로`. 형식은 `timestamp,open,high,low,close,volume`이고 timestamp는 ISO 문자열 또는 ms입니다.

### 거래소별 설정

| 거래소 | symbol | exchange 설정 | 비고 |
|---|---|---|---|
| 바이낸스 선물 | `BTC/USDT:USDT` | `id: binance, market_type: future` | 롱·숏, 손절/익절을 거래소 주문으로 걸어 둠 |
| 바이비트 선물 | `BTC/USDT:USDT` | `id: bybit, market_type: future` | 같음 |
| 업비트 현물 | `BTC/KRW` | `id: upbit, market_type: spot, sandbox: false` | 롱만, 봇이 현재가로 손절/익절 감시 (봇이 꺼지면 손절이 안 됨) |

### 안전장치

- 실거래는 `live.enabled: true`와 `--live`가 **둘 다** 있어야 동작합니다.
- 선물에서 진입한 뒤 손절 주문이 실패하면 즉시 시장가로 청산합니다.
- 손절을 옮길 때는 새 손절 주문을 먼저 걸고 나서 기존 주문을 취소합니다.
- 시작할 때 거래소에 봇이 모르는 포지션이 있으면 실행을 거부합니다.
- 마감된 지 반 봉 이상 지난 신호는 무시합니다. 진입 직전에 현재가로 손익비를 다시 확인합니다.
- 최소 주문 수량에 못 미치면 주문하지 않습니다. 설정 키에 오타가 있으면 바로 오류가 납니다.

## 실데이터 백테스트 결과

- **데이터**: Bitstamp BTC/USD 1분봉([ff137/bitstamp-btcusd-minute-data](https://github.com/ff137/bitstamp-btcusd-minute-data))을 1h/4h로 묶음
- **기간**: 2019-01 ~ 2026-10
- **비용**: 수수료 편도 0.05%, 슬리피지 0.02%

**기본 설정(4h 진입 + 1d 방향, strict) 전 기간**

| 항목 | 값 |
|---|---|
| 거래 수 | 203 (롱 139 / 숏 64) |
| 승률 | 26.6% |
| Profit Factor | 0.97 |
| 거래당 평균 | -0.01R |
| 총 수익률 | **-3.1%** (같은 기간 단순 보유 +2,167%) |
| 최대 낙폭 | -16.0% |

연도별 합계(R): 2019 -5.3 · 2020 -7.3 · 2021 +4.5 · 2022 +1.0 · 2023 -0.7 · 2024 +9.9 · 2025 -0.5 · 2026 -3.0

**변형 비교**: 2019–2023 구간에서 비교하고 2024–2026 구간으로 확인했습니다. 설정 24가지 중 2019–2023 구간에서 플러스인 조합은 하나도 없었습니다.

| 조합 | 2019–23 거래당 R | 2024–26 거래당 R |
|---|---|---|
| 1h + 4h 방향, 셋업 둘 다 (loose) | -0.13 | -0.28 |
| 1h + 4h 방향, strict | -0.11 | -0.23 |
| **4h + 1d 방향, strict (기본값)** | **-0.06** | **+0.06** |
| 4h + 1d 방향, strict, 스윕만 | -0.04 | +0.44 (21건, 표본 부족) |

해석:

- 1시간봉은 손절 폭이 좁아서 수수료가 거래당 약 0.18R을 잡아먹습니다. 수수료를 빼기 전에도 마이너스였습니다.
- 4시간봉 + 일봉 추세 필터가 가장 덜 나빴습니다. 그래서 기본값으로 정했지만, **수익 전략이라고 볼 근거는 없습니다.**
- 2024년 이후 "스윕만" 조합의 플러스 성적은 거래가 21건뿐이고 2019–23 구간에서는 마이너스였습니다. 우연일 가능성이 높습니다.

## 폴더 구조

```
autotrader/
├─ bot/
│  ├─ config.py      설정 (dataclass 기본값 + YAML)
│  ├─ indicators.py  EMA, ATR, 스윙 피벗, 볼륨 프로파일
│  ├─ levels.py      지지·저항 구간(zone) 묶기
│  ├─ strategy.py    방향 필터, 스윕/리테스트 신호, 손절·목표·손익비
│  ├─ trade.py       포지션, 손절/익절 판정, 손익 계산 (백테스트·실거래 공용)
│  ├─ risk.py        수량 계산, 일일 손실 한도, 연속 손실 휴식
│  ├─ backtest.py    봉 단위 백테스트와 통계
│  ├─ broker.py      PaperBroker(모의) / CcxtBroker(실거래)
│  ├─ live.py        실시간 루프, 상태 저장, 텔레그램 알림
│  └─ __main__.py    명령줄 (demo / fetch / backtest / run)
├─ tests/            규칙·미래참조 없음·주문 흐름 테스트
├─ config.example.yaml
└─ RULES.md          채널 개념 → 규칙 대응표, 확인 필요 항목
```

## 한계

- 실제 거래소와의 주문 연동(`CcxtBroker`)은 가짜 거래소 객체로 호출 순서만 테스트했습니다. 실제 거래소에서는 검증하지 못했습니다(개발 환경에서 거래소 API 접속이 막혀 있었음). 거래소마다 조건부 주문 처리가 다를 수 있으니 **반드시 테스트넷에서 먼저 확인하세요.**
- 백테스트는 봉 단위입니다. 같은 봉에서 손절과 익절이 모두 닿으면 손절로 처리합니다(보수적). 펀딩비는 반영하지 않았습니다.
